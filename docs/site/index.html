A RISC-V microcontroller for Tiny Tapeout

Tiqora

Time, as an operand.

A 32-bit RV32E processor that adds four bits per clock, plus a timing unit that stamps pin edges and fires output pulses on the exact clock tick software asked for. It is built for SkyWater sky130 through Tiny Tapeout and fits, as synthesized cells, in 67% of a 2x2 block of tiles. Its layout does not yet fit.

On a Basys 3, simulated

The same RTL on a Digilent Basys 3, with the flash and RAMs emulated in block RAM and the board's USB port as Tiqora's serial port. Press play, or drag through the run: button presses are timestamped to the 20 ns tick, LED 0 blinks from the timebase, and a typed key comes back.

recorded simulated board, not a real one make -C fpga/basys3 record runs the whole board design in Icarus Verilog and fpga/basys3/rec_basys3.sv writes down the LEDs, display, buttons and serial port; this board is drawn from that file, cycle by cycle. Timing is shortened for simulation (8 clocks per UART bit, LED 0 toggling every 40,000 ticks instead of every 25,000,000). Nothing has run on a real Basys 3 yet.

What goes in and what comes out

Seven questions

What is Tiqora?

A complete microcontroller for one Tiny Tapeout design slot of 2 × 2 tiles: an RV32E core (the 32-bit RISC-V base with 16 registers, here x1 to x15 plus x0), a QSPI memory controller, a UART, GPIO and a timing unit, behind the 24 Tiny Tapeout pins. It runs C compiled with Clang. The core is nibble-serial: one 4-bit adder does every 32-bit add in eight clocks, which is what makes the processor small.

Eleven Xpulse instructions on RISC-V's custom-0 opcode read the timebase, arm deadlines, wait for them and pop timestamped events. Example: tarm x1, x0 then twait x1 makes TRIG0 rise on tick x1 exactly, with no software in the path. See it happen.

What enters?

Code and data from the Tiny Tapeout QSPI Pmod: a 16 MB flash holds the program and two 8 MB RAMs hold data, reached four bits at a time over uio[7:0]. Pin edges on ui_in[7:0], timestamped by the timing unit. Serial bytes on ui_in[3], for printf-style I/O or, with ui_in[7] high at reset, to load a program with no flasher. One 50 MHz clock and an active-low reset.

What happens inside?

After reset the QSPI controller wakes both memory chips in six steps, then the core fetches. Each instruction is a pass of eight clocks while the register file rotates past the single adder, least significant nibble first. Xpulse instructions talk to the timing unit directly, with no bus access. Reset and wake-up · a fetch at the pins · an add, nibble by nibble.

What comes out?

On uo_out[7:0]: TRIG0 and TRIG1, the deadline outputs; EVT (events queued) and OVF (one was lost); HALT and ILLEGAL; a heartbeat; and UART TX on uo_out[4]. Any of them can be turned into a GPIO output instead. The pinout and every block.

What exists today?

SystemVerilog RTL, a C toolchain set-up and libraries, a bootloader, testbenches, a Basys 3 FPGA build and Tiny Tapeout packaging. No chip and no board run. The layout fails placement at 2x2 (DPL-0036), so the tile size is still an open decision. Physical design status.

What is proven or measured?

measured 490 RTL checks in 17 suites, 6 cocotb tests, the official RISC-V tests 37/37, gate-level simulation of the sky130 netlist, and synthesized cell area. estimate logic timing before layout. failed place and route at 2x2. not yet formal proofs, signoff timing, a shuttle, silicon. The evidence ladder.

What can I try?

Every tour on this site is regenerated by one command, and so is every check behind it:

# Icarus Verilog 12 and Python 3
git clone https://github.com/Normansrule/tiqora-skywater130
cd tiqora-skywater130
make -C test tour                # the recorded tour: 15 checks
python3 docs/tools/traces.py     # turn it into this site's fixtures
make -C test sim                 # every suite

Or change the operands of the recorded add in the nibble lab and watch the eight phases recompute.
